# 06: Coordination and independent review

The filename is retained for canonical module compatibility. Roles are generic;
no vendor plugin or internal rule link is required.

| Role | Responsibility |
|---|---|
| Coordinator | Own accepted revision, scope, shared manifests/lockfiles, authorization, attempts and delivery |
| Author | Produce scenario/config/capture/render artifacts within the assigned checkout and file scope |
| Independent reviewer | Inspect the actual source-bound outputs, captions and transitions; return separate findings |

One writer per checkout. A reviewer does not patch the author's checkout. Use a
fresh independent review context and an available execution adapter; launching a
role or naming a reviewer is not evidence that review happened. For this
project's coding work only OpenAI coding models are permitted: baseline author
`gpt-6.1-sol high`, a different planner/reviewer model and fresh `gpt-6-astra`
review. These are project assignments, not a required plugin dependency for an
external user. Actual model/usage stay null without host evidence.

Every attempt records in Markdown: accepted commit/source hashes, authorized
files, expected result, required checks, CPU/RAM/operation and attempt limits,
start/deadline, stop conditions, owner and evidence directory. Bound diagnostic
and corrective attempts separately. The portable runtime uses explicit 900s
operations within each 4,800s CLI command; these bounds do not authorize repeated
unlimited work or new expenses/access/publication.

At a deadline stop that attempt, inspect its artifacts and failure cause, record
remaining criteria and appoint a concrete next bounded action. Do not silently
extend the same pass or reduce full-video/check requirements. An autonomous
project continues until its agreed result is complete, unless the owner pauses
it. A handoff or time limit ends an attempt, not the project. Confirm the next
executor actually starts; a queue entry alone is insufficient. Report a real
external blocker with evidence and the exact input needed, while continuing
independent authorized work. Give the coordinator concise progress snapshots
about every ten minutes without adding a scheduler.

Review receives the exact source/config/image identity, original capture/render
receipts, all three MP4s, recording/log hashes, sealed config/policy, storyboard
and transition indexes/sheets, and caption declarations. Reviewer watches the
actual outputs in all three formats, checks every required sheet and dangerous
transition, and traces each caption to visible recording evidence. A technical
source review alone does not accept video content.

Record reviewer identity, attempt/time, actual model evidence or null, source
and config hashes, receipt paths, media/recording hashes, findings and verdict in
external review Markdown. Fill the existing TSV declarations using their exact
vocabulary in [07](07-final-check.md); preserve hashes. No autoaccepting blanks or
copying verdicts from a different SHA. Changed media requires fresh bound proof
and review. Automated gates validate declarations and binding, not human honesty.

Delivery requires verify 0 plus the independent review record and the accepted
brief. Publication, deploy, paid calls and license representations remain separate
authorized release decisions. Full runtime evidence is owned by the coordinator.
